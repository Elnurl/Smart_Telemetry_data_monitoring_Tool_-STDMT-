02 · Why we need it

Niyə bu alət lazımdır

Peyk əməliyyatında telemetriya fasiləsiz gəlir. Excel / skript / “gözlə baxmaq” gecikmə, buraxılmış xəbərdarlıq və izah olunmayan qərarlar yaradır.

Həcm

Battery, bus voltage, current, thermal — eyni anda bir neçə kanal. İnsan hər saniyəni izləyə bilməz.

Kontekst

Eclipse zamanı temperatur düşməsi gözləniləndir. Nominal rejimdə eyni siqnal anomaliyadır. Alət bunu mission mode ilə ayırır.

Məsuliyyət

AI özbaşına train/start/email etməməlidir. Operator təsdiqi olmadan təhlükəli əməliyyat yoxdur.

04 · Purpose

Əsas məqsəd

SDA v4.0 peyk telemetriyasını real vaxtda müşahidə etmək, anomaliyanı aşkarlamaq, operatora izah etmək və təsdiqlənmiş addımı təklif etmək üçündür.

Detect

Anomaly, drift, OBS pozuntusu, pattern / risk.

Explain

Niyə Warning? Mode-normal, yoxsa həqiqi anomaliya?

Act (human)

Retrain, alert, start/stop, SOP — yalnız operator Approve.

08 · Monitoring tabs

Hər tab = bir telemetriya kanalı

  • Data source — CSV və ya folder (məs. BatteryTemperature, BusVoltage, TotalBusCurrent).
  • Schedule — Continuous (interval), Scheduled (UTC slot), On-Demand (bir cycle).
  • Models — bir tab-da bir neçə model; train, metrics, remove.
  • Health — Idle → Monitoring → Healthy / Warning / Critical.
  • OBS — əməliyyat limitləri; pozuntu log-da görünür.
  • Email alert — tab konfiqində; SMTP Administration-dan.

09 · Models

Analiz və ML seçimi

UI-də 40+ model adı var. Əməliyyat üçün sabit backend-lər istifadə olunur (Isolation Forest, LSTM, CNN, ARIMA və s.).

Classical

Isolation Forest, LOF, One-Class SVM, IQR, Z-Score, XGBoost, Random Forest.

Deep / sequence

LSTM, LSTM-AE, CNN, Autoencoder, GRU — time-series üçün.

Trend / fusion

ARIMA, Prophet; multi-agent fusion (LSTM-AE + CNN + trend) bir qərara birləşir.

10 · Mission modes

Eclipse ≠ anomaliya

Hər tab-ın FSM rejimləri threshold-u genişləndirir və ya sıxır. M-LLM log-ları “mode-normal” vs həqiqi anomaliya kimi ayırır.

ModeNə baş verir
NominalStandart həssaslıq (scale 1.0)
EclipseGözlənilən thermal/power sapması — false positive azalır (məs. ×1.5)
Safe mode / maneuverDaha sərt və ya fərqli hədd; tab konfiqində tənzimlənir

11 · SatOps Agent

Operator köməkçisi — chatbot deyil

Danışır

Salam / sual — təbii cavab. Fleet report yalnız ops sualında.

Baxır

Live tab status, metrics, explain_anomaly, knowledge (SOP/PDF).

Təklif edir

Create tab, train, start/stop, alert, SOP Word draft — Pending Agent Drafts.

İcra etmir

Sən Approve etmədən heç nə yazılmır / start olunmur / email getmir.

12 · Safety

Propose → Approve

Bu, departament üçün əsas qaydadır: AI məsləhətçidir, komanda rəhbəri deyil.

  • Agent propose_* çağırır → draft Home → AI Assistant → Pending Agent Drafts.
  • Operator Approve və ya Reject.
  • Retrain siqnalları ayrıca Acknowledge tələb edir.
  • Lokal knowledge: faylları data/knowledge-ə qoy, Rebuild Knowledge.
  • Token/API yalnız localhost; JWT /v1 üstünlük.

13 · How to use

Canlı demo — 8 addım

  1. run.bat — login (admin / analyst).
  2. Home → Fleet Overview — mövcud tab-ların statusu.
  3. + New tab — məs. data/BatteryTemperature.csv, Continuous, 1–2 model.
  4. Tabı aç → Model Management → Train (ən azı bir model).
  5. Start Monitoring — status Idle-dan çıxmalıdır.
  6. Home-da health: Healthy / Warning / Critical.
  7. AI Assistant — “which tab needs attention?” və ya “hola” (söhbət, briefing yox).
  8. Əgər draft varsa → Approve. SOP/PDF üçün Rebuild Knowledge.

16 · What it is not

Sərhədlər (dürüst)

  • Bulud LLM / ChatGPT bağlantısı yoxdur — qəsdən.
  • Digital twin / orbital simulator yoxdur — real telemetriya + lokal model.
  • Agent “Start all tabs” düyməsi deyil; hər tab ayrıca start olunur.
  • Kiçik lokal model səhv route edə bilər; Approve həmişə son sözdür.
  • Email yalnız konfiqurasiya olunmuş SMTP ilə işləyir.
